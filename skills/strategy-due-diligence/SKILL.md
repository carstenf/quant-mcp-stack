# Strategy Due Diligence (pick list -> filter check -> ML4T backtest -> diagnostics -> TradeBlocks -> report)

Use when someone hands over a list of picks/trades from a third party (newsletter, author, fund, colleague; often traded by hand, not generated by a backtester) and wants to know whether the strategy is real, robust and investable. **Default stance: you do not know whether the history was filtered** (cherry-picked periods, removed weeks, edited lists, back-filled before publication, best of many variants). The skill must find out what can be found out and price in what cannot. Output: short chat summary + PDF report in the user's language (default: multi-page with a stand-alone executive summary on page 1; one-page C-level version only on request).

## House rules first
If the user has their own conventions (a workflow/entry skill, project folder for research files, a holdout rule and protocol, a chart style file, a factor library), they override the defaults below. Look for them before starting (user's skills, memory, project files) and follow them; name every deviation from this skill in the report.
- Holdout: re-testing a third party's published list is usually not research on one's own strategy, but if the user keeps a holdout rule, check whether it covers this case and log the run in their protocol.
- Storage: default is the ML4T workspace; use the user's project folder if they have one (`run_python` / `job_start` accept `cwd`).

## Golden rule: use the tested tools, do not reinvent them
- Backtest = **ml4t-backtest** engine (via `scripts/picklist_backtest.py`). Never hand-roll return simulations.
- Metrics, bootstrap confidence intervals, benchmark comparison, Deflated/Probabilistic Sharpe, expected max Sharpe, MinTRL, reality check, factor models, signal/IC analysis = **ml4t-diagnostic**. Data = **ml4t-data** / the ML4T MCP data tools.
- Before writing any analysis code, look it up: ML4T MCP `list_library_functions(query=...)`, `describe_function(name)`, `get_recipe()`. Only if nothing fits, write own code and say so in the report.
- Robustness on the realised equity/trade tape (edge decay, rolling/period metrics, walk-forward, Monte Carlo, stress, regime, block comparison, backtest vs. actual) = **TradeBlocks MCP**.
- Own code ONLY for real gaps: parsing the pick file, random-portfolio and baseline tests against a universe, concentration, charts, the report.
- Methodology reference: Jansen, *Machine Learning for Algorithmic Trading* 3e (survivorship and point-in-time universes ch. 2, cost sensitivity and baselines ch. 16, costs and capacity ch. 18). If the user has Jansen's ML4T agent skills installed (e.g. `ml4t-survivorship-bias`, `ml4t-transaction-costs`, `ml4t-backtest-overfitting`, `ml4t-deflated-sharpe`), consult them and name deviations.

## 0. Intake (ask only if unknown)
- Rules as claimed: when the list is known (must be before the entry open -> no look-ahead), entry/exit timing (e.g. Monday open to next Monday open), weighting (equal), number of names, holding period, filters.
- **Track-record type** (always ask; it sets the evidence level) - who produced the record and how:
  - `audited`: real money with verifiable statements (broker statements, third-party verified performance, GIPS composite) - real fills and costs;
  - `self-reported`: real money, but only the vendor's own figures - counts as `paper-vendor` until statements are seen;
  - `paper-independent`: signals recorded by an independent party (the user, a colleague) as they arrived, ideally with timestamps (mails, chat, a ledger) - the vendor could not omit or back-date anything; fills simulated (often open/close without costs);
  - `paper-vendor`: paper or model portfolio published by the vendor with timestamps - out-of-sample only from the first verifiable publication, but the vendor chose what to publish;
  - `unknown`: unknown or hypothetical (e.g. produced by a backtest, reconstructed) - in-sample only.
  Also ask: who recorded it, since when, is every signal included (no gaps), are there timestamps? Independently recorded lists can be added to a timestamp ledger afterwards with their original timestamps as evidence.
- **Provenance** (the key questions for a third-party list): Since when is each list verifiably public with a timestamp (emails, posts, newsletter archive, archive.org snapshot)? Was any part delivered or reconstructed later? Did the rules ever change? Does the vendor publish other strategies/lists (only the survivors shown?). Does the vendor publish an own equity curve or real fills?
- **Traded rule:** which holding period / rule was actually traded or recorded before anyone looked at the results? -> `--traded-hold` (no DSR over holds, PSR instead).
- **Vendor variants:** how many lists/strategies/models does the vendor run or has run? This sets `--assumed-vendor-trials` (unknown -> 100).
- Benchmarks: S&P 500 total return (adjusted SPY, not the price index ^GSPC) always; add Nasdaq 100 (adjusted QQQ) and the dominant sector/country ETF.
- Costs: baseline 0,2 % per side (commission + slippage) plus a gross run and a cost grid (default 0,1 % / 0,5 %); raise the baseline for small caps, OTC ADRs and low dollar volume.

### How the intake answers drive the evaluation
| Intake answer | Parameter | Effect |
|---|---|---|
| Track-record type | `--record-type` | evidence grade: only `audited` and `paper-independent` can reach A; `self-reported` counts as `paper-vendor`; `unknown` = in-sample only, verdict at most Watch unless the tradability audit (section 8) succeeds |
| First verifiable publication / live start | `--published-from` | in-sample vs. out-of-sample split; MinTRL and the paired benchmark test on the out-of-sample part decide |
| Number of vendor lists/strategies | `--assumed-vendor-trials` | multiple-testing hurdle: PSR of the excess return against the expected max Sharpe of that many zero-skill strategies |
| Rules and list timing | engine timing, `--delays` | execution model; look-ahead check |
| Costs, liquidity, real fills | `--cost-bps`, `--cost-grid` | net results, break-even cost, capacity; without real fills the evidence grade uses the conservative (highest) cost level of the grid |
| Holding period actually traded/recorded | `--traded-hold` | that rule is the only trial: PSR instead of DSR over the holds; other holds = robustness only |
| Benchmark | `--benchmark` | paired test, factor alpha |

**Evidence grade** (`_evidence_grade`, page 1 of the report): **A** = a record nobody could filter (`audited`, or `paper-independent` that is complete and timestamped), out-of-sample period >= MinTRL, paired benchmark test p < 0,05 and still significant at the assumed vendor trials - without real fills on the conservative cost level; **B** = genuine out-of-sample evidence that does not meet all of this (too short, not significant, or recorded by the vendor); **C** = no verifiable out-of-sample period (`unknown` or no start date). Only grade A can support "Buy" on the record alone. A grade B because of length is not a provenance problem: say so and give the remaining time to MinTRL.

## 1. Data
Prices: use the best curated source available (e.g. the user's Sharadar build: point-in-time, delisted names, total-return OHLC) before free sources such as Yahoo. If a share of the picks is missing in that source (often OTC ADRs), ask whether to redistribute their weight or hold cash, and quantify the effect: run the list once with the old source on the full list, once with the old source restricted to the covered names, once with the new source - this splits the change into universe effect and price-source effect (report it). Normalise ticker spelling (BRK.B vs BRK-B) between picks and price panel and check `tickers_without_prices` is empty.
- Pick file -> `picks.csv` with columns `week` (first trading day of the week, YYYY-MM-DD), `ticker` (Yahoo/US format, '.'->'-'), `rank`. Excel or other files received from the user: keep a parquet copy of the raw file next to the run.
- Prices: daily OHLCV panel (timestamp, asset, open, high, low, close, volume), **split- and dividend-adjusted consistently for open and close** (a split-day jump in opens is a data error), incl. benchmark tickers.
  - **Survivorship:** use a source that includes delisted names (e.g. Sharadar SEP for US-listed stocks); Yahoo only for names it lacks (OTC ADRs, foreign lines), and say per ticker which source was used. Yahoo has no delisted names.
  - **Delisting returns:** for every name whose prices end inside the sample, determine the reason (e.g. Sharadar actions: acquisition, bankruptcy, delisted) and build `delist.csv` (asset, terminal return): acquisition = offer premium if known else 0, bankruptcy/liquidation = -1,0, other = 0. Unknown reason -> `--delist-return` (default 0) and add a stress run with -1,0.
- Factors: Fama-French 5 + momentum, daily, via MCP `fetch_factors` (datasets ff5, mom) or ml4t-data `FamaFrenchProvider`. Note the last factor date.
- Universe for the random-portfolio and baseline tests: **point-in-time** membership (e.g. `sharadar_universe` / historical index constituents). Today's constituents from Wikipedia are outcome-dependent (survivors) - only as a last resort, and say so.

## 2. Provenance and filter check (third-party lists)
The history is in-sample until proven otherwise. Only the period after the first verifiable publication is genuine out-of-sample.
1. **Data checks** (`data_checks.json` from the script): missing weeks (a skipped week; holiday weeks starting on Tuesday are not flagged), duplicate rows, list size changing, identical consecutive lists, tickers without prices, names picked before their first price or after their last price, unusual weekday of the week start, list turnover per week. Missing weeks can be removed bad weeks; report each finding.
2. **Publication split** (`--published-from`): metrics before vs. after the first verifiable publication (`_publication_split`; the post part has bootstrap CIs and the paired benchmark test). A strong drop after publication is the classic sign of a fitted or filtered record (cf. McLean & Pontiff 2016 for published anomalies).
3. **Unknown number of vendor trials** (`_vendor_trials_sensitivity`): PSR of the leader's excess return against the expected maximum Sharpe of N zero-skill strategies (`compute_expected_max_sharpe`) for N = 1, 10, 100, 1000, plus the N at which it stops being significant. A record that survives only N <= 10 is fragile if the vendor runs many lists.
4. **Entry-delay test** (`_entry_delay`): entry 1, 2, 5 trading days later. Genuine weekly signals decay smoothly; an edge that collapses with a one-day delay, or picks whose run-up happened before the pick week, point to late or back-dated lists.
5. **Vendor curve vs. replication:** if the vendor publishes returns or fills, import them into TradeBlocks next to the replicated tape and run `compare_backtest_to_actual` / `analyze_discrepancies`. Systematic gaps (vendor better in exactly the bad weeks) indicate filtering.
6. **Not testable here** - list explicitly: survivorship of the vendor's own strategies (only winners shown), undisclosed rule changes, selection of the start date. Treat these as risks with a haircut, not as passed.

## 3. Backtest on the ML4T engine
Use `scripts/picklist_backtest.py` from this skill's folder (if the skill was installed without its folder, fetch it from `https://raw.githubusercontent.com/carstenf/quant-mcp-stack/main/skills/strategy-due-diligence/scripts/picklist_backtest.py`), write it and `picks.csv` into the run folder, then start it with `job_start`:
`python picklist_backtest.py --picks picks.csv --prices <panel>.parquet --out out --holds 1,2,4,8,12,26 --cost-bps 20 --cost-grid 10,50 --delays 1,2,5 --benchmark SPY --exclude <theme tickers> --published-from <date> --delist-map delist.csv --record-type <audited|self-reported|paper-independent|paper-vendor|unknown> --assumed-vendor-trials <N> [--traded-hold <weeks>]`
- Execution: weights set on the last bar before the pick week, filled NEXT_BAR at OPEN (= Monday open), equal weight over the FULL list, 98 % gross, fractional shares. Names without a price stay in cash (no reweighting to survivors). Names leaving the list are closed with `close_position` (exact quantity; a target weight of 0 can produce rejected "position reversal" sells). `_rejected_orders` must be 0 for every variant, otherwise the tape is not what was intended - check before using any number. Delisted names get the terminal return on the bar after their last price, then stay flat until sold.
- Holding H weeks = H staggered buy-and-hold tranches (1/H capital each), summed. All tranches start invested in week 0 (ramp-up), so for long holds the first H weeks over-weight the first lists - mention it for H >= 12.
- Outputs per variant: equity.parquet, trades.parquet, TradeBlocks `tb_tradelog.csv` + `tb_dailylog.csv`; `summary.json` with
  - per variant: PortfolioAnalysis stats (CAGR, vol, Sharpe, Sortino, Calmar, MDD, alpha/beta, IR, up/down capture), annualised turnover, `uncertainty` (block-bootstrap 95 % CIs + PSR p-value), `vs_benchmark` (paired bootstrap strategy minus benchmark: Sharpe, CAGR and MDD difference, information ratio, each with CI; p-value; probability the strategy wins),
  - evidence: `_evidence_grade`; cohort: `_selection_adjustment`, `_dsr_excess_vs_benchmark` (DSR on excess returns over the net hold variants), `_whites_reality_check`, `_min_trl_best_net_hold`, `_vendor_trials_sensitivity`,
  - `_holding_period_choice`, `_cost_grid` (net CAGR per hold and cost level, gross row), `_entry_delay`, `_publication_split`,
  - `_pick_stats` (+ `_pick_stats_ex_theme`): per-pick win rate, avg win/loss, payoff ratio, share of a 3:1 target, top-10 contributors and their share, liquidity, capacity estimate,
  - `_warnings` (daily Sharpe > 2 -> check fill timing first; picks without prices; gaps; picks before first price).
- Exit-rule tests (stop loss, take profit, trailing stop) use the engine's `StopLoss`, `TakeProfit`, `TrailingStop` rules, not hand-made price checks.
- Count variants honestly. **Was the rule fixed before the results were seen?** Ask in the intake which holding period was actually traded/recorded. If one was (e.g. a colleague paper-traded the 1-week rotation), pass `--traded-hold <weeks>`: it is the leader and the only trial, so the DSR collapses to the PSR (no selection to deflate) and the other holds are robustness checks only - say so in the report and do not show a DSR. Only if holds were compared and the best is taken (no traded rule), the DSR counts all net hold variants. Pass any further variant you looked at with `--extra-trials`. Cost-grid, delay and ex-theme runs are sensitivity checks, not candidates. The unknown number of vendor variants (`_vendor_trials_sensitivity`) still applies either way.
- Holding-period choice (no preferred horizon): always run all holds. Recommend the hold with the highest NET CAGR at the assumed costs among reliable holds (>= 4 full holding periods). For each longer hold report the break-even cost per side vs. the shortest hold and the cost at which net CAGR reaches zero. Recommend a longer hold only if it is within ~1 pp net or costs above break-even are realistic, and say so.

## 4. Diagnostics with ml4t-diagnostic
- Factor model: `compute_factor_model(returns, FactorData(...), hac=True)` on daily returns AND on weekly (Monday-to-Monday) returns. Foreign/ADR-heavy lists have asynchronous closes: report both; only claim a style tilt that is significant in both.
- Signal ranking: `analyze_signal` (rank IC, quantiles) with the rank as signal, or rank-IC per week.
- Optional: `compute_pbo` when many parameter variants were scanned; `compute_return_attribution` / `compute_rolling_exposures`; `WalkForwardCV` / `CombinatorialCV` when parameters are fitted.
- Look-ahead: check publication timing (intake, section 2). If you compute a signal yourself, run `audit_lookahead` on the signal function.

## 5. Robustness with TradeBlocks
`import_csv` (tradelog + dailyLogPath, plBasis net_includes_fees) per variant, then:
- `get_statistics` (marked-curve Sharpe/Sortino/Calmar with T-bill rf, CAGR, MDD, time in drawdown).
- `analyze_edge_decay` (period trends with p-values, rolling metrics, walk-forward efficiency). Use its quarterly trend p-values and walk-forward IS/OOS Sharpe; ignore the Monte-Carlo regimeComparison absolute values (margin-based for stock tapes).
- `run_monte_carlo` with `resampleMethod: marked-daily` (stationary block) for 1-year return and drawdown quantiles.
- `get_period_returns` / `get_performance_charts` for monthly tables; `stress_test` / `analyze_regime_performance` if the period covers stress or VIX data is available; `compare_blocks` for variants; `compare_backtest_to_actual` / `analyze_discrepancies` against vendor returns (section 2).
- TradeBlocks "trades" are engine round trips (names held across weeks are merged); per-pick win rate and payoff come from `_pick_stats` (its share of a 3:1 target is reported only for Minervini-style trade strategies).

## 6. Gaps filled with own code
- **Baseline (Jansen ch. 16):** equal-weight portfolio of the point-in-time universe with the same Monday-open protocol and costs. Separates "the universe did well" from selection skill; report strategy minus baseline.
- **Random-portfolio test:** 10,000 runs, each week N random names from the same point-in-time universe (plain and sector-matched), same timing; p = share of runs with CAGR >= strategy; also per half, post-publication only, and ex-theme.
- **Concentration:** contribution of the dominant theme and top tickers to excess return (start from `_pick_stats`), Herfindahl index and effective number of contributors, sector/country shares; trimming top/bottom 1/5/10 % of pick returns at weekly-portfolio level.
- **Costs and capacity (Jansen ch. 16/18):** cost grid from `_cost_grid` (conservative / baseline / optimistic); safety margin = gross excess return / round-trip cost per turnover (>= 2,5 robust, < 1,5 likely unprofitable); for small caps use a square-root impact estimate instead of a flat rate; capacity from `_pick_stats.capacity_aum_usd` (AUM at 1 % / 5 % of median 20-day dollar volume); share of names < 5 M / < 1 M USD, OTC ADRs.

## 7. Interpretation rules
- p-values primary, as decimals (p = 0,07), t-value in brackets; thresholds p < 0,05 (t >= 2), quant hurdle p < 0,003 (t >= 3); DSR > 0,95; PBO < 0,20.
- Results depend on sampling frequency (daily vs weekly) - state which one each number uses; prefer the engine's daily marked curve for risk, weekly non-overlapping returns for inference on weekly strategies.
- "Beats the benchmark" needs the paired test: `vs_benchmark` p < 0,05 and the CI of the Sharpe difference / information ratio above 0. A high absolute Sharpe with a CI that includes the benchmark is not outperformance.
- Report CIs next to point estimates (e.g. Sharpe 1,98 [0,56; 3,42]).
- **Out-of-sample first:** the verdict rests on the verified post-publication period; the pre-publication history counts only as supporting evidence. If there is no verifiable publication date, the whole record is in-sample.
- Investable only if: verified out-of-sample period >= MinTRL and significant on its own (paired benchmark test p < 0,05), random-test p < 0,05 in both halves and post-publication, factor-model alpha p < 0,05 (ideally < 0,003), DSR > 0,95 (PSR for a pre-specified traded rule) and still significant at a realistic number of vendor trials, no significant edge decay or post-publication break, entry-delay decay smooth, costs/capacity acceptable at the conservative cost level, no unexplained data-check findings. Otherwise: "Watch / small satellite": record the vendor's lists live from now on with timestamps (the only hard proof), re-test in 12 months, with explicit scale-up and stop criteria.
- Always state what is not tested (vendor survivorship, real fills, crisis periods, global factors, taxes, FX).

## 8. Tradability audit (for grade B/C - make an unknown strategy tradable or reject it)
The record itself cannot become reliable; reliability has to come from data the vendor could not influence. Pick the path that fits and say which one in the report.
1. **Rules can be reconstructed** (the list follows recognisable criteria, e.g. momentum + valuation): rebuild the signal generator on point-in-time data from the factors/rules you can identify, measure the overlap with the vendor's lists (share of names matched per week, rank correlation), and treat it from then on as an own strategy: research only on data the user allows for research, then a single pre-registered test on untouched data (if the user keeps a locked holdout, this needs their explicit permission for the run - the exemption for re-checking third-party lists no longer applies once it becomes an own strategy). Count every rebuild variant for the DSR.
2. **Black box** (lists only, no rules): incubate forward. From today every list is stored on receipt in an append-only ledger with UTC timestamp and SHA-256, ideally committed to a git remote for an independent timestamp (and flagged if it arrived after the open it is meant for). Pre-register before the first list: minimum duration (MinTRL from the backtest's Sharpe, at least 6 months), the test (paired excess return vs. benchmark on weekly non-overlapping returns, checked monthly with a sequential bound so repeated looks do not inflate errors), stop rule (e.g. drawdown beyond the backtest's 95 % Monte-Carlo quantile or excess-return t < -1 after 13 weeks), and stages: paper -> small real money (e.g. 10 % of target size) -> full size, each only after its hurdle.
3. **Returns explained by known factors** (factor alpha not significant, high R²): no need to trust the vendor - trade the factor exposure directly (factor ETF or own factor portfolio), cheaper and transparent.
Outcome, with explicit criteria in the report: **tradable** (grade A, or path 1 passed its untouched-data test, or path 2 passed its pre-registered hurdle), **incubating** (path 2 running; state the next decision date and hurdle), **reject** (stop rule hit, path 1 failed, or nothing beyond factor exposure - then recommend path 3).

## 9. Report (HTML -> PDF, A4, page footer with page numbers and "not investment advice")
Page 1 executive summary: verdict badge (Buy / Conditional / Watch / Reject), evidence grade (A/B/C) and tradability outcome (tradable / incubating / reject, with path), 3-sentence key box, 6 KPI tiles (CAGR, CAGR after costs, Sharpe [CI], win rate with payoff ratio (% of 3:1 only for Minervini-style trade strategies), random-test p, factor-alpha p), checklist table (criterion, result, hurdle, met/borderline/not met; include provenance: track-record type and who recorded it, verified OOS length, publication break, vendor-trials break-even), next steps.
Sections: 1 strategy, provenance & data (data-check findings, sources per ticker, delistings); 2 performance (equity + drawdown charts, KPI table, in-sample vs. verified out-of-sample); 3 skill or luck (p-value reader box, random-portfolio histogram, baseline comparison, cumulative excess, regression scatter, DSR / vendor-trials / MinTRL / White's RC table); 4 where returns come from (factor loadings chart with CI, return attribution waterfall, daily vs weekly table); 5 concentration & robustness (contributors, HHI, sectors, trim/ex-theme table); 6 implementation (holding-period table, cost grid and break-evens, safety margin, entry delay, exit rules, rank analysis, liquidity and capacity); 7 edge decay & Monte Carlo (TradeBlocks); 8 risks (severity, likelihood, mitigant; untestable filter risks) + bull/bear case; 9 recommendation, tradability audit path & decision criteria (incl. incubation plan if applicable); appendix methodology, glossary, sources.
Charts: the user's chart style file if they have one; otherwise white background, Inter/Arial, no frame, light y-grid, y-label with unit, series names in line colour under the title (no legend box), solid equal-width lines, max 5 series, palette #2a78d6 #eb6834 #1baf7a #eda100 #c2407a #6250d6, blue = positive / red = negative only for signed values, take-away caption under each chart. **Background follows the medium:** the PDF always uses light (white-background) charts; dark charts only for chat/phone. If the style file has modes, render both (`chart_x.png` dark, `chart_x_light.png` light) from one script kept in the report folder. Check every PNG before building the PDF.
Report text rules: state the execution timing in plain words in section 1 and the appendix (entry day and price, exit day and price, whether weekends are held) and verify it against the trade log fill prices; every regression/factor table shows the coefficient AND its p-value for every factor, not only the significant ones, and names each factor in words (e.g. Investment = CMA, conservative minus aggressive investing firms); say why each multiple-testing statistic is there (DSR: several variants were tried and the best was taken); the glossary is written for readers without statistics or finance background and covers every term used in the report; when numbers change versus an earlier report, give the main reason with its size and say whether the data source changed.
