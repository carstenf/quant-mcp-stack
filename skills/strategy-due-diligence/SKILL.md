# Strategy Due Diligence (pick list -> ML4T backtest -> diagnostics -> TradeBlocks -> report)

Use when someone hands over a list of picks/trades (often traded by hand, not generated by a backtester) and wants to know whether the strategy is real, robust and investable. Output: short chat summary + PDF report in the user's language (default: multi-page with a stand-alone executive summary on page 1; one-page C-level version only on request).

## Golden rule: use the tested tools, do not reinvent them
- Backtest = **ml4t-backtest** engine (via `scripts/picklist_backtest.py`). Never hand-roll return simulations.
- Metrics, bootstrap confidence intervals, benchmark comparison, Deflated/Probabilistic Sharpe, MinTRL, reality check, factor models, signal/IC analysis = **ml4t-diagnostic**. Data (prices via Yahoo, Fama-French factors) = **ml4t-data**.
- Before writing any analysis code, look it up: ML4T MCP `list_library_functions(query=...)`, `describe_function(name)`, `get_recipe()`. Only if nothing fits, write own code and say so in the report.
- Robustness on the realised equity/trade tape (edge decay, rolling/period metrics, walk-forward, Monte Carlo, stress, regime, block comparison) = **TradeBlocks MCP**.
- Own code ONLY for real gaps: parsing the pick file, random-portfolio test against a universe, per-pick trade statistics, charts, the report.

## Requirements (both MCP servers must be connected)
- **ML4T MCP server** with `run_python`, `fetch_prices`, `fetch_factors`, `list_library_functions`, `describe_function`, `get_recipe` (ml4t-backtest >= 0.2, ml4t-diagnostic >= 0.1.9, ml4t-data >= 0.3). All code below runs through `run_python` in its workspace; datasets live under `data/prices`, `data/factors`.
- **TradeBlocks MCP server** (Docker image `romeo345/tradeblocks-mcp` or `npx tradeblocks-mcp <data-dir>`). The exported CSVs must be copied to a path the TradeBlocks server can read (its data dir). On a [quant-mcp-stack](https://github.com/carstenf/quant-mcp-stack) server both run on one host: write the CSVs from `run_python` to `$TRADEBLOCKS_DATA/<block>/` and pass `/data/<block>/tb_tradelog.csv` (the path inside the TradeBlocks container) to `import_csv`.
- Setup of both servers from scratch: see `SETUP.md` in that repo.
- If a server is missing: stop, say which one, and point to its setup; do not substitute own code.
- Network for downloads (Yahoo Finance, Kenneth French Data Library, Wikipedia for index constituents). If blocked: say which domain and ask for data files; never invent data.

## 0. Intake (ask only if unknown)
- Rules as traded: when the list is known (must be before the entry open -> no look-ahead), entry/exit timing (e.g. Monday open to next Monday open), weighting (equal), number of names, holding period, any filters.
- Was it traded live with fixed rules? Then the history is genuine out-of-sample. Real fills available? Prefer them; otherwise simulate and say so.
- Benchmarks: S&P 500 always; add Nasdaq 100 and the index of the dominant sector (e.g. ^SOX).
- Costs: default 0,2 % per side (commission + slippage) plus a gross run.

## 1. Data
- Pick file -> `picks.csv` with columns `week` (first trading day of the week, YYYY-MM-DD), `ticker` (Yahoo format, '.'->'-'), `rank`. Report data issues: duplicate weeks, weeks with too many/few rows, identical consecutive lists, tickers without prices (survivorship).
- Prices: daily OHLCV panel (timestamp, asset, open, high, low, close, volume) as parquet incl. benchmark tickers, via ml4t-data (Yahoo provider) or MCP `fetch_prices`.
- Factors: Fama-French 5 + momentum, daily, via ml4t-data `FamaFrenchProvider` or MCP `fetch_factors` (datasets ff5, mom). Note the last factor date.

## 2. Backtest on the ML4T engine
Write `scripts/picklist_backtest.py` and `picks.csv` into the ML4T workspace (via `run_python`), then run there `python picklist_backtest.py --picks picks.csv --prices $ML4T_DATA/prices/<name>.parquet --out out --holds 1,2,4,8,12,26 --cost-bps 20 --exclude <theme tickers>`.
- Execution: weights set on the last bar before the pick week, filled NEXT_BAR at OPEN (= Monday open), equal weight, 98 % gross, fractional shares, delisted names exit at last price.
- Holding H weeks = H staggered buy-and-hold tranches (1/H capital each), summed.
- Outputs per variant: equity.parquet, trades.parquet, TradeBlocks `tb_tradelog.csv` + `tb_dailylog.csv`; `summary.json` with
  - PortfolioAnalysis stats (CAGR, vol, Sharpe, Sortino, Calmar, MDD, alpha/beta, IR, up/down capture),
  - `uncertainty` = `compute_backtest_uncertainty`: block-bootstrap 95 % CIs for Sharpe, Sortino, CAGR, MDD, Calmar + PSR p-value,
  - `vs_benchmark` = `compute_paired_uncertainty`: paired bootstrap of strategy minus benchmark (Sharpe, CAGR and MDD difference, information ratio, each with CI; p-value; probability the strategy wins),
  - cohort-level: `compute_selection_adjustment` (leader, expected max Sharpe under noise, MinTRL; on absolute returns), DSR on excess returns vs benchmark over all variants, MinTRL, White's reality check.
- Exit-rule tests (stop loss, take profit, trailing stop) use the engine's `StopLoss`, `TakeProfit`, `TrailingStop` rules, not hand-made price checks.
- Count variants honestly; DSR n_trials must include every variant looked at.
- Holding-period choice (no preferred horizon): always run all holds (script default 1,2,4,8,12,26). Recommend the hold with the highest NET CAGR at the assumed costs. For each longer hold report the break-even cost per side at which its net CAGR equals the shortest hold's (from gross CAGR gap and cost drag per bp). Recommend a longer hold only if it is within ~1 pp net or costs above break-even are realistic (small caps, ADRs/OTC, low liquidity), and say so explicitly. Holds with fewer than 4 full holding periods in the sample are "not reliable" and never the recommendation. The script writes all of this to `summary.json` -> `_holding_period_choice` (net/gross CAGR, cost drag per bp, break-even bps, reliability, best reliable hold).

## 3. Diagnostics with ml4t-diagnostic
- Factor model: `compute_factor_model(returns, FactorData(...), hac=True)` on daily returns AND on weekly (Monday-to-Monday) returns. Foreign/ADR-heavy lists have asynchronous closes, so daily loadings can differ strongly from weekly ones: report both; only claim a style tilt that is significant in both.
- Signal ranking: `analyze_signal` (rank IC, quantiles) with the rank as signal, or rank-IC per week.
- Optional: `compute_pbo` when many parameter variants were scanned; `compute_return_attribution` / `compute_rolling_exposures` for rolling attribution; `WalkForwardCV` / `CombinatorialCV` when parameters are fitted.
- Look-ahead: for a given pick list check publication timing (intake). If you compute a signal yourself, run `audit_lookahead` on the signal function.

## 4. Robustness with TradeBlocks
`import_csv` (tradelog + dailyLogPath, plBasis net_includes_fees) per variant, then:
- `get_statistics` (marked-curve Sharpe/Sortino/Calmar with T-bill rf, CAGR, MDD, time in drawdown).
- `analyze_edge_decay` (period trends with p-values, rolling metrics, walk-forward efficiency). Use its quarterly trend p-values and walk-forward IS/OOS Sharpe; ignore the Monte-Carlo regimeComparison absolute values (margin-based for stock tapes).
- `run_monte_carlo` with `resampleMethod: marked-daily` (stationary block) for 1-year return and drawdown quantiles.
- `get_period_returns` / `get_performance_charts` for monthly tables; `stress_test` / `analyze_regime_performance` if the period covers stress or VIX data is available; `compare_blocks` for variants.
- Note: TradeBlocks "trades" are engine round trips (names held across weeks are merged); compute per-pick win rate, avg win/loss and % of a 3:1 target separately from the weekly pick returns.

## 5. Gaps filled with own code
- Random-portfolio test: 10,000 runs, each week N random names from a comparable universe (e.g. S&P 1500 from Wikipedia, plain and sector-matched), same Monday-open timing; p = share of runs with CAGR >= strategy; also per half and ex-theme.
- Concentration: contribution of the dominant theme and top tickers to excess return; trimming top/bottom 1/5/10 % of pick returns at weekly-portfolio level.
- Liquidity: median dollar volume per traded name, share < 5 M / < 1 M USD, OTC ADRs.

## 6. Interpretation rules
- p-values primary, as decimals (p = 0,07), t-value in brackets; thresholds p < 0,05 (t >= 2), quant hurdle p < 0,003 (t >= 3); DSR > 0,95; PBO < 0,20.
- Results depend on sampling frequency (daily vs weekly) - state which one each number uses; prefer the engine's daily marked curve for risk, weekly non-overlapping returns for inference on weekly strategies.
- "Beats the benchmark" needs the paired test: `vs_benchmark` p < 0,05 and the CI of the Sharpe difference / information ratio above 0. A high absolute Sharpe with a CI that includes the benchmark is not outperformance.
- Report CIs next to point estimates (e.g. Sharpe 1,98 [0,56; 3,42]).
- Investable only if: random-test p < 0,05 in both halves, paired benchmark test p < 0,05, factor-model alpha p < 0,05 (ideally < 0,003), DSR > 0,95, no significant edge decay, costs/capacity acceptable, track record >= MinTRL. Otherwise: "Watch / small satellite, track live with fixed rules, re-test in 12 months" with explicit scale-up and stop criteria.
- Always state what is not tested (real fills, crisis periods, global factors, taxes, FX).

## 7. Report (HTML -> PDF, A4, page footer with page numbers and "not investment advice")
Page 1 executive summary: verdict badge (Buy / Conditional / Watch / Reject), 3-sentence key box, 5 KPI tiles (CAGR, CAGR after costs, Sharpe, random-test p, factor-alpha p), checklist table (criterion, result, hurdle, met/borderline/not met), next steps.
Sections: 1 strategy & data; 2 performance (equity + drawdown charts, KPI table); 3 skill or luck (p-value reader box, random-portfolio histogram, cumulative excess, regression scatter, DSR/MinTRL/White's RC table); 4 where returns come from (factor loadings chart with CI, return attribution waterfall, daily vs weekly table); 5 concentration & robustness (contributors, sectors, trim/ex-theme table); 6 implementation (holding-period table incl. costs, exit rules, rank analysis, liquidity); 7 edge decay & Monte Carlo (TradeBlocks results); 8 risks (severity, likelihood, mitigant) + bull/bear case; 9 recommendation & decision criteria; appendix methodology, glossary, sources.
Charts: white background, Inter/Arial, no frame, light y-grid, y-label with unit, series names in line colour above the plot (no legend box), solid equal-width lines, max 5 series, palette #2a78d6 #eb6834 #1baf7a #eda100 #c2407a #6250d6, blue = positive / red = negative only for signed values, take-away caption under each chart. Check every PNG before building the PDF.

## 8. Deliver
Send the PDF and key charts; short reply with a table of the main numbers; explicitly correct earlier numbers if a later step changes them.
